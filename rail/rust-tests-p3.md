## 本轮修复

1. **原生快照传输峰值。** 直接解码 CORE 中的请求，解码完成后释放大型输入缓冲，避免再复制一整包输入。值编码器先收集符号和精确长度，再直接写最终数值缓冲，移除完整中间数值树的副本；原始与 packed wire 字节布局不变，并增加固定编码断言。56,000 项历史旅程恢复、真实原生压缩和在途存档通过，WASM 上限保持 256 MiB。
2. **冷旅程模板的重复存储。** Rust 内将冷模板直接准备为共享旅程对象，提交身份时移动对象，省去全目录数值模板包。稀疏整数目录采用小页存储，删除最后一项时释放空页。内部身份文本使用可逆字典编码；数值、旅程次序和合约身份保持一致。
3. **恢复输入树的生命周期。** 从 checkpoint 移走旅程目录，不再在 seed、runtime 和队列构造中重复复制；队列接管后释放已消费的输入树。内部恢复校验仍检查完整旅程与人数守恒。
4. **Worker 摘要和站点显示缓存。** 完整快照同时返回当前原生摘要；恢复和交接丢弃旧 nativeView，防止其覆盖新队列统计。异步站点视图缓存按模拟时间及编辑版本失效。原生计划视图中的财务与客流字段使用当前世界值，避免显示旧账户。
5. **连续编辑的原生命令路径。** 调度、票价、加站、删站和删线用例改用实际会话命令。补齐结构化几何命令：Rust 校验点位与折点数量、计算几何和费用，按轨道方向存放折点；旧运行列车保留原几何。测试同时检查无效命令原子回滚、免费预览、一次收费、乘客旧票价、未受影响线路、位置连续和守恒。
6. **冷元数据的原生观测。** 提供只读存储统计，测试 2,600 项加权目录经过两批原生元数据准备；推进仅跨主线程一次，59 字节请求，无 JS 权重 getter 回读，也无未变化的原生权重扫描。原先截获旧 engine_cycle RPC 的断言改为检查现行原生边界与实际状态。
7. **诊断测试输入。** 合成候车、站外和列车模型改为脱离 arena 的显示 DTO；真实原生句柄单独负责存档。保留 Worker 与主线程诊断结果精确比较、只读断言、9 MiB JSON 往返和失败后最后成功存档不变的检查。

额外验证：重构前后的 WASM 在整数/加权模式、不同峰段与跨日场景下，36 份完整世界、checkpoint 和摘要逐字段一致。Rust 新增目录页生命周期、冷模板准备/提交、身份字典可逆及精确 wire 编码回归。源码边界仍覆盖 80 个模块、1,563 个函数、69 个页面脚本和 3 个引用 Worker。

## 剩余问题

- 旧东京全线网的加权客流预热仍有内存峰值失败；本轮已解决大型历史存档的传输峰值，未据此宣称整个旧世界预热已修复。
- 历史连续模拟用例仍直接修改创建后的 JS 时间、余额、贷款、到达模式、站点限制和世界结构，或调用已移除的同步 reconcile；需要逐项改用原生输入和命令，并保留原业务验证目标。
- 完整旧世界、生命周期、费用及保存轨迹与现行原生完整循环仍有差异；旧 passenger-only、旧 RPC、预算和快照基线需要继续逐字段核实。

失败套件全部计入，独立 CI 最终门禁维持真实失败退出码。主干仅同步源码与报告，使用 skip-ci 提交。
