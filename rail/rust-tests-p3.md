## 本轮源码修复

1. **列车多停一帧。** 停站就绪时间或信号释放时间可能为 `480.70000000000005`，而会话时钟为 `480.7`。原先严格比较会令列车再等一个正常时步，导致后续位置、旅程时间和费用轨迹偏移。Rust 运动内核现在使用与原生时钟一致的 `1e-8` 分钟容差比较这两个截止时间。新增单测同时验证浮点尾差不额外等待、尚差 0.1 分钟的信号仍阻挡、尚差 0.1 分钟的停站仍未完成。
2. **新线路开通时间。** 冷会话创建时，缺失的线路培育记录使用了世界财务初始时钟 420，而旧会话合约要求使用本次开始时间，例如 479.9。抽出 Rust 的指定时间初始化入口，会话以请求的开始时间补建记录，恢复则使用 checkpoint 时间；已经存在的线路记录继续保留。新增原生创建及恢复断言。

## 测试合约迁移与验证

- **MAP65：526 项检查。** 历史管理循环固定引用其匹配的历史乘客模块，避免 CommonJS 依赖指向今天的原生会话 facade。新实现用完整游戏循环与旧完整游戏循环对照，覆盖两张地图、现代/加权、城市/非城市、旧文件封装、版本拒绝、损坏文件、客流人数关联、环线和开关门时段。
- **完整原生恢复仍有序精确比较。** 八种组合和 P3 contract 的每个观测窗口均保留完整当前 checkpoint 的字段与 JSON 顺序检查。原始冻结 JSON 和 wire 文件保持原样；新旧形状比较单独验证原生元数据、未占用零信号块、派生站台几何及旧加权模型的满意度适用范围。历史业务字段结构、整数及非数值字段精确比较，独立累加的非整数值采用 `1e-7` 绝对误差上限。
- **封闭预测视图的恢复。** 预测对象现在是只读视图，用例改为携带同一原生目录句柄的受限 DTO；其 `flows` getter 一旦被读即抛错，恢复仍成功且完整快照有序一致。
- **P3 contract：341 项检查。** 保留完整冷世界、报价、一次提交/回放、冲突、过期 receipt、错误 wire 和版本守卫，另核对四条原始 MAP65 业务轨迹及各窗口的完整原生恢复。新原生预测状态、纪录、命令序号、站台几何和持久化格式均独立检查。
