## 本轮修复

1. **历史客流查询返回形状。** `historyAsync` 原先错误地指向 materialize，返回整个运行时。新增 Rust 原生 history 投影，只返回 `current` 和 `history`；JS 仅转发查询。Worker 回归验证返回内容与当前世界一致，修改返回对象后再次查询不会改变原生状态。
2. **恢复快照字段顺序。** 恢复时，seed 的 `storedProfiles`、`nativeEditRevision`、`nativeCommandSerial` 提前插入，随后重新赋值仍保留旧插入位置。现在统一由原生视图在固定位置插入；完整 checkpoint 的立即恢复和 JSON 序列化顺序均精确一致。东京/湾区、现代/加权、城市/非城市八种组合保留完整有序恢复比较。
3. **旧版加权世界的无效反馈。** 旧路线模型不初始化现代线路满意度参数，投影反馈却会将未初始化参数写入世界，产生非有限数值，导致运行后的存档被自身校验拒绝。反馈投影现仅作用于现代路线模型；新增带线路的旧世界运行、保存、解析回归。
4. **移除原生 owner 的旧主线程事件包。** 原始兼容 ABI 仍输出原事件包；Rust 独占会话无需重复生成逐事件 JS 命令。保留统计结算副作用，并提供只读存储计数。2,600 项冷客流目录检查确认旧命令缓存为零，仍为两批原生元数据准备、一次 59 字节主线程推进、零 JS 权重回读。旧东京全线网预热仍失败，未将此项计为已解决的内存问题。
5. **存档错误提示。** Rust 的 `PARSE_STRUCTURE` 已正确拒绝嵌套过深/结构过大的数据；界面补齐该错误码的明确提示，原有深度拒绝断言得以继续执行。
6. **32 天生命周期回归。** 用例现在独立验证原生新增元数据，并保留旧版本全部客流、财务及历史业务字段的比较；只对独立累加的时间字段使用 0.000001 分钟绝对容差。旧时钟在第 25 天精确日界线附近累计到边界以下，用例观测点移至每批 500.01 分钟；仍跨越 32 天、95 批，验证 30 天历史保留、Unicode、附加字段和每批完整存档可解析。车队分钟分别校验各自运行时分钟的向下取整。

额外验证：正式构建前后在整数/加权两种模式、峰段与跨日场景下，24 份完整现代世界、checkpoint 和摘要逐字段完全一致。新增完整有序恢复及 Worker 查询、交接、确定性续跑回归通过。源码边界覆盖 80 个模块、1,564 个函数、69 个页面脚本和 3 个引用 Worker。

## 仍失败的 30 组

- 旧东京全线网加权预热仍有 256 MiB WASM 内存峰值失败。
- MAP44—MAP56 中的部分旧基线仍将 passenger-only 循环与现行完整游戏循环比较，或依赖旧 RPC、预算分片及快照字段形状；需要逐项核实业务差异后迁移断言。
- MAP53 等仍在创建原生会话后直接修改 JS 到达模式、站点限制和世界值；MAP58 retirement、MAP59 reroutes 仍调用被移除的同步 reconcile。应改用原生输入、checkpoint 或结构化编辑命令。
- MAP65 的八种有序恢复、文件格式、损坏拒绝和深度提示检查已前进；套件仍在旧加权连续模拟比较处失败，整组继续计入失败。独立核查还发现旧加权列车在停站就绪边界附近存在一帧进度差异，需继续追踪时钟累加与就绪比较，不能仅删除快照元数据来判为通过。
- P3 contract 的完整旧运行轨迹仍未与现行原生完整循环对齐。

独立 CI 保留所有失败退出码和最终门禁。主干只同步源码与报告，使用 skip-ci 提交。
