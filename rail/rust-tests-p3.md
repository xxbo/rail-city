## 本轮新增修复

1. Worker 交接直接读取原生完整世界，区分内部交接恢复与公开存档校验；390、419.9 分钟可交接，公开文件仍保留 420 分钟下限。修改 JS 显示余额不会影响原生交接账户。
2. 预制目录分块进入 Rust，追加数值表时重映射线路、枢纽和服务索引；无效分块保持已有目录不变。80,001 与 151,056 项目录通过，WASM 仍限制为 256 MiB。
3. 预测目录导出采用小元数据加原始 f64 表，避免将全部数值装箱成通用 Value 再传输；诊断复用已安装目录，运营分组直接读取 Rust 合约表。东京 183 站、21 线路用例恢复。
4. 每日权重修改在原生确认时同步总量、活跃目录数、时间与版本；已消费的版本不再全量扫描，Worker 回包同步主线程原生目录的只读查询视图。
5. 队列摘要和站点/列车查询直接读取原生队列；站点分线候车包括换乘旅客，空汇总保持正零，避免为小查询构造完整存档树。
6. Worker 启动失败且尚未交接时继续使用原主线程 Rust arena；交接完成后的故障仍保持失败语义。增加原生句柄最终释放，并补齐反复恢复测试的显式 dispose。
7. 需求 Worker 移除已经无用途的 passengers.js 依赖，直接传输 Rust 预测目录，修复浏览器脚本加载时缺少 Runtime 的启动错误。VM 脚本导入顺序与结构化克隆测试通过。
8. Rust 公开纪录合并保留字段顺序、缺省值、负数及有符号零语义，成就投影保持旧 JSON 属性顺序；3,953 项历史比较恢复。存档版本号拒绝布尔值/字符串隐式转换，非有限数字返回明确错误。
9. 路由公开视图保留旧稀疏数组形状与裁剪边界；更新已经移入 Rust 的 JSON 导入断言，保留 2,965 项精确路由比较。
10. 历史故障测试改为当前原生编码/存储失败入口，保持最后成功存档及后续重试断言；运营观察用例使用真实结构化命令、异步需求替换与快照。Node 20 对懒加载数组的比较显式物化两侧，所有数值比较仍保留。

## 剩余问题

失败清单以机器报告为准，不能全部归为过时测试：

- 旧东京全线网的加权客流预热仍触及 WASM 内存峰值；大预制目录的输入与传输问题已修复，但该旧世界的实际运行峰值需要独立优化。
- 多组历史运行时回归在创建原生会话后直接修改 JS 余额、贷款、到达模式、站点限制或世界结构，或调用已移除的同步 reconcile。需改用原生输入/命令并保留原业务断言。
- 新会话统一完整游戏循环，并携带原生所有权、预测版本、观察与纪录字段；旧 passenger-only 轨迹和旧生命周期基线仍有时间、统计及完整快照差异，需要逐字段核实，不能靠删字段或放宽全部数值比较处理。
- 历史预算/Worker 用例还截获旧 RPC、JS 时钟和扫描接口。需要迁移观测位置，同时保留预算截止、故障恢复、退休列车、连续保存等验收目标。

独立 CI 保留失败退出码；本次范围不含真实浏览器、手工游戏或部署。主干同步使用 skip-ci 提交。

## 上轮已修复项

1. 队列快照写入顺序与 Rust 读取顺序不一致：收入、上车人数和出行目的计数会互换。统一顺序，并验证完整存档恢复后继续运行的状态一致性。
2. 新批次从初始财务输入读取当天运营成本，覆盖已累计值。每批从原生统计状态带入最新累计成本，恢复分线与全网运营成本的对应关系。
3. 日期计算与 15 分钟统计槽的浮点容差不一致，日界线附近出现负槽位及 `RUNTIME_STATISTICS_CLOCK`。统一边界容差并补 Rust 回归。
4. 财务与运行时分别累计时间，读取快照后会出现微小时间变化。世界财务投影采用会话的同一个原生时间值。
5. 兼容预测入口忽略已有 preparedDefinitions；按普通线路解析展开后的快慢车服务时还会 panic。保留准备好的目录，按展开计划解析服务，并让无效服务引用返回结构化错误。
6. 普通预测被替换为 Proxy，破坏调用者原有 DTO 的可克隆性。兼容入口仅登记原生目录句柄，保留调用者对象；现代预测直接复用数值目录。
7. 旧存档 pack/parse 的公开返回结构、纪录缺省值和错误文本发生漂移。兼容投影仍由 Rust 生成，原生会话的完整导入校验继续保留。
8. 存储读取的布尔警告字段被误当作原生错误代码，导致回退读取抛出空消息。区分警告结果与字符串错误。
9. 无统计模块的旧运行时，在日历批次中多写一个统计数字，导致队列包长度断言失败。按统计模块是否存在生成正确帧。
10. 旧预测路径与边重复深拷贝。Rust 内共享不可变路径并在修改时复制，逐条编译数值目录，避免再完整构造一份定义树。大旧线网仍有后续内存问题，见下节。

历史回调式编辑用例使用 scripts/helpers/management-compat.cjs 将候选输入提交给原生资产事务验证和收费；浏览器生产 API 仍使用结构化命令。原生专项直接使用生产会话 API，覆盖收入/上车/目的计数、完整恢复续跑、累计成本、显示对象隔离、非法输入恢复、快慢车服务、Worker 交接及 Worker/本地续跑一致性。

通过的专项还包括 MAP14 的 24 日客流培育与守恒、MAP24 的存档往返、MAP60 的 380 项交路比较、MAP61 的 424 项校验、MAP63 的 764 项资产比较、MAP64 的 1,656 项完整诊断比较。该历史轮次的源码边界检查覆盖 80 个模块和 1,557 个函数，保留未知入口、动态 Worker、未审查函数的拒绝测试；开发夹具只允许明确的 Node 分支和固定白名单。
