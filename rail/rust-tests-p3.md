## 已修复的真实错误

1. 队列快照写入顺序与 Rust 读取顺序不一致：收入、上车人数和出行目的计数会互换。统一顺序，并验证完整存档恢复后继续运行的状态一致性。
2. 新批次从初始财务输入读取当天运营成本，覆盖已累计值。每批从原生统计状态带入最新累计成本，恢复分线与全网运营成本的对应关系。
3. 日期计算与 15 分钟统计槽的浮点容差不一致，日界线附近出现负槽位及 `RUNTIME_STATISTICS_CLOCK`。统一边界容差并补 Rust 回归。
4. 财务与运行时分别累计时间，读取快照后会出现微小时间变化。世界财务投影采用会话的同一个原生时间值。
5. 兼容预测入口忽略已有 preparedDefinitions；按普通线路解析展开后的快慢车服务时还会 panic。保留准备好的目录，按展开计划解析服务，并让无效服务引用返回结构化错误。
6. 普通预测被替换为 Proxy，破坏调用者原有 DTO 的可克隆性。兼容入口仅登记原生目录句柄，保留调用者对象；现代预测直接复用数值目录。
7. 旧存档 pack/parse 的公开返回结构、纪录缺省值和错误文本发生漂移。兼容投影仍由 Rust 生成，原生会话的完整导入校验继续保留。
8. 存储读取的布尔警告字段被误当作原生错误代码，导致回退读取抛出空消息。区分警告结果与字符串错误。
9. 无统计模块的旧运行时，在日历批次中多写一个统计数字，导致队列包长度断言失败。按统计模块是否存在生成正确帧。
10. 旧预测路径与边重复深拷贝。Rust 内共享不可变路径并在修改时复制，逐条编译数值目录，避免再完整构造一份定义树。大旧线网仍有后续内存问题，见下节。

历史回调式编辑用例使用 scripts/helpers/management-compat.cjs 将候选输入提交给原生资产事务验证和收费；浏览器生产 API 仍使用结构化命令。原生专项直接使用生产会话 API，覆盖收入/上车/目的计数、完整恢复续跑、累计成本、显示对象隔离、非法输入恢复、快慢车服务、Worker 交接及 Worker/本地续跑一致性。

通过的专项还包括 MAP14 的 24 日客流培育与守恒、MAP24 的存档往返、MAP60 的 380 项交路比较、MAP61 的 424 项校验、MAP63 的 764 项资产比较、MAP64 的 1,656 项完整诊断比较。源码边界检查现覆盖 80 个模块和 1,557 个函数，保留未知入口、动态 Worker、未审查函数的拒绝测试；开发夹具只允许明确的 Node 分支和固定白名单。
