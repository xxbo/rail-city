| 入口 | 本阶段归属 |
| --- | --- |
| 运行快照、导出 | RuntimeOwner 在同一次串行请求中投影世界、财务、队列与列车，原生封装并编码；正常保存返回文本、字节数和少量元数据 |
| JSON 及签名 | json_codec.rs 有界 UTF-8 解析/编码；save.rs 原生签名，兼容历史 JS 指数数字表示 |
| 格式及旧档 | persistence.rs 保留格式1、第7代、runtimeVersion1；裸世界及第6代复用 bootstrap 迁移；未知显式版本拒绝覆盖 |
| 自动保存、排队 | Owner 保有10秒观察时钟、活动/待处理票据、最新请求合并、顺序写入队列、计数和成功状态 |
| 纪录 | Rust 保有7项逐字段最大值规则，合并运行、当前地图文件、已有目标地图文件及目标地图持久纪录；不同地图的当前局纪录隔离 |
| 导入确认 | 当前运行会话保有候选、单调 token 与变更代数；确认时重建完整候选并验证，冻结原会话至数据库提交成功或取消 |
| 存储绑定 | JS 只执行 IndexedDB 事务、原值比对写入、Storage 调用和 Promise/RPC 对应；数据库回退、成功确认及旧键清理条件由 Rust 决定 |

原数据库 guanchao-rail-checkpoints/version1/saves 和地区键保持。写事务比对读取时的原值，出现其他标签页更新时报告冲突；失败事务保留原记录。旧 localStorage 键只在写事务成功且内容仍为迁移时的原文时清理。Owner 在提交成功后更新观察到的检查点文本，失败保留前值；队列也保留最近成功结果。开始新游戏先排空旧捕获及写入，避免旧会话晚写覆盖新局。

导入流程：暂停 → Rust 解析及验证候选 → 界面展示预览 → 计算候选预测 → Rust 检查 token/会话变更代数并完整恢复临时运行 → 返回原生编码字节并冻结原会话 → 数据库事务 → 确认并切换地图。临时候选释放目录引用，无存活的第二运行 Worker。预览期间编辑/运行推进使凭证失效；成功提交前所有失败路径保留现有运行和原存档。提交后的页面导航以已落库记录为准。

编码约定：上限64MiB UTF-8、深度80、200万值。拒绝危险键、非有限 JSON 数字、非法转义及未配对 UTF-16 代理；合法中文与代理对按 UTF-8 保留。对象 Missing 省略，数组 Missing 和内部 NaN/Infinity 时间哨兵写 null，负零写0，与历史 JSON 存档相同。未知扩展成员在有序 Value 中保留；导入后覆盖规范字段，保留信封扩展。数字由 Rust 最短表示编码，旧签名通过原生解析后的同序载荷比较兼容科学计数法。

源码收益：保存和导出退出“完整运行对象回主线程 → 再传编码 Worker”的链路；正常路径只跨线程传文本及少量元数据。纪录长度按运行候选缓存，运行投影只合并少量记录字段。额外成本包括导入完整校验、候选恢复、文本穿过 ABI 与持久化原值比对；实际耗时、内存及收益比例待统一测量。

源码新增大于9MiB中文/emoji往返、非法文件、未知运行版本、排队合并/失败后保留成功结果、纪录最大值等测试用例，尚未运行。统一验收还需覆盖两地图导入、活动编辑使预览失效、运行整数/加权客流守恒、坏关联、数据库故障/冲突、旧键 CAS 清理及关闭页面时最后成功存档。
