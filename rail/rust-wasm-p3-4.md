## 已接入的路径

- RuntimeOwner 提供 command / preview / demand / undo，和 pulse 共用会话队列。提交携带命令编号及编辑修订；Rust 保留最近128条回执，拒绝编号复用、过期回执及修订冲突，重复请求返回当前视图及原回执。
- 编辑在 Rust 候选世界内完成结构化命令、校验、报价、库存与扣款，再调用原生迁移规则处理候车、站外、换乘、退役列车、旧几何和旧票价。候选运行区构造完成后才交换权威状态。提交前检查乘客总量、定义/leg引用与现金重建一致性。
- 暂停编辑的一个撤销检查点及目录引用由 Rust 持有。UI 只保留撤销令牌和展示预测引用。撤销核对令牌及游戏时刻，恢复对应世界、现金和出行状态，保持修订单调递增。
- 后台需求结果提交到运行会话；主线程发送预测目录，不下载运行队列再回灌。Rust筛选有效合同并切换私有目录；失败保留旧目录。目录引用随运行区、候选失败、替换、撤销和关闭释放。
- 45,000实际定义且距上次整理至少5分钟时，原生运行区整理全部队列、站外、车内、换乘、等待时间引用；55,000编辑整理边界保持原值。大预测目录仍使用惰性原生定义，无JS物化回退。
- UI普通编辑、设施、购车、站名/线路名称颜色及撤销改走会话事务。生产入口使用结构化描述；旧 reconcile/rebase 和回调编辑适配留给P3-6兼容收口，原生会话拒绝宿主事后修改世界再reconcile。
- 浏览器启动时用创建结果直接交接运行Worker，避免首次编辑额外请求完整快照。预览保留只读冷查询用于同步界面报价；新增会话预览入口查询权威财务。

## 与JS迁移前相比

编辑、需求替换与撤销的运行状态处理集中到Rust，删去UI编辑前的完整runtime下载、JS重映射与runtime重新上传。主线程仍负责提交结果的显示投影。收益预期是减少传输、对象分配和主线程停顿；尚无实测速度或内存数字。

为保持候选失败不污染现状，目前使用Rust内部完整冷视图构造候选运行区，再原子替换；内部复制和重建仍有成本，旧区、候选区及一个撤销检查点可同时占用内存。该实现尚未证明峰值内存更低。

## 后续统一验收与剩余边界

需要统一编译后对照：编辑失败完全无副作用、连续/重复命令、晚到预测、退款/库存、贷款与编辑交错、等价撤销、旧票价改签、无路取消、候车/站外/车内/换乘总量、旧几何退役，以及超过45k/55k目录和多次编辑的压力场景。

城市与观察定时调度仍按P3-5推进。自动保存和显式导出继续使用现有完整快照接口，归P3-7；P3-4删除的是编辑/迁移本身的物化往返，自动保存尚会独立请求存档快照。旧模型/回调公开API归P3-6，Worker故障/超时/恢复归P3-8。
