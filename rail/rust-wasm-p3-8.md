# P3-8：界面、Worker 与发布绑定收口（源码阶段）

2026-11-10，承接主干 P3-7 / 96fb2aa5ae6df0193e5195dc121bdd4d56768803。源码目标推进到 core-v33、会话 fixture-v9、runtime_session_abi=6、缓存73。编译、测试和浏览器运行留至统一验证。

Rust platform.rs 接管 Worker 租约、请求票据、超时、迟到回包、销毁与提交结果未知的判定。worker-client.js 只保留 Worker/Timer 句柄、消息转发与 Promise 对应；运行和需求线程共用此端口。运行请求超时后停止该会话，拒绝自动重放。Native offer 控制运行脉冲积压，忙时后续帧只显示已有快照。只读查询线程发生故障后可建立新租约，旧回包和已结算任务的旧定时器均由 Rust 拒绝。

ui.js 的主线程需求备用计算、旧模拟钟推进和旧诊断 Worker 分支已移除，诊断复用运行会话的权威预测；10秒刷新选择在 Rust。首次需求线程失败显示重新加载入口，运行故障暂停并保留成功存档。

view_model.rs 输出只读财务、预计还款、逐线满意度、全网加权分数、车站候车/容量/拥挤标记、日期、成就门槛和金额转换。view-model.js 提供只读投影与显示标签，财务、候车、线路与运营中心组件消费这些投影；过滤、中文排序、金额/百分数文案及布局保留界面。ridership.js 的旧初始化、事件/分时、统计与财务投影辅助代码移入 scripts/fixtures/rail-p3-8-ridership.cjs，仅供 Node 兼容回归；浏览器暴露原生查询端口，运行状态只由 RuntimeOwner 更新。旧回归经过参考辅助代码的结果须与原生会话验收区分。

诊断指纹与实际旅程身份键统一使用原生 JSON 编码，当前 Rust 源码退出 rail_host.json_utf8，Rust 单测也可生成这些键。rail_math 的数值、熵与单调时间原语登记于 scripts/rail-platform-bindings.json；Rust 选择熵调用、持有模型 RNG，并决定模拟推进。为保持浮点边界，系统数学原语暂保留，替换实现须独立比对。

发布改为 scripts/rail-public-assets.json 的显式资源名单，排除历史 WASM、性能报告和开发夹具；仅列当前 core-v33。旧二进制继续保存在开发仓中，未构建的新目标不会伪装成已验收产物。保留当前冷兼容端口与地图渲染 Worker，全部生产入口需在 P3-9 按函数重新审查；旧 AST 盘点为历史记录，未自动刷新。

相较此前 JS，主要收益是消除重复线程/备用编排、界面侧游戏决策及宿主 JSON 往返，并减少发布夹带的历史资源。DTO 编码与多实例驻留仍有成本，尚无本阶段性能测量。P3-8 的最终 UI-only 边界与浏览器完整性验收继续由 P3-9 检查，当前交付为源码实现。
