## 1. 终点与边界

用户目标：JS 仅保留界面，界面之外的应用逻辑全部使用 Rust。

最终 Rust 负责：世界初始化、区域/地形与模型输入处理、全部现代及兼容模型、预测与合同目录、列车/乘客/财务/城市/历史的唯一可写状态、时间债务与暂停/恢复、随机数、命令校验/提交/撤销、后台任务的修订与失效策略、诊断与观察、存档编解码/迁移/恢复、持久化排队与失败恢复。

最终手写 JS 负责：DOM/CSS/SVG/Canvas、相机/缩放/拾取/屏幕坐标、输入控件与草稿、面板/主题/图层、纯展示排序和文字格式化、动画插值。表单可提供即时提示，但业务有效性与提交结果由 Rust 决定。建设草稿可以在 JS；实际轨道长度、合站、容量、资产与可建判断在 Rust。

浏览器桥接是部署机制，不是新的业务层豁免：
- 文件选择器和下载按钮可由界面触发；数据解析、验证、恢复与落库策略在 Rust。
- IndexedDB、Storage、Fetch、Worker、时钟等由 Rust 平台适配层通过浏览器绑定访问。优先采用可固定版本和可复现构建的 wasm-bindgen/web-sys；P3-0 先验证工具链及绑定方案。现有 ABI 的薄桥接可作为过渡。
- 自动生成的 JS 绑定，以及确有平台限制的最小宿主桥接，只转发 API/字节/事件；不保留模型选择、默认值、重试/回退策略、存档排序或业务状态。
- rAF、页面可见性与性能时钟作为外部事件输入；Rust 决定时间债务、游戏推进量和后台页行为，保留当前行为。
- DOM/Blob 的实际对象可留在浏览器；把文件内容解释成游戏状态的代码归 Rust。
- UI 私有偏好（相机、主题、标签、面板）可在界面保存；游戏速度、运行意图、纪录、区域存档选择和恢复规则归 Rust。
- 原始地图、地名、统计来源等可作为 JSON/二进制静态数据；模型派生与配置默认值在 Rust。静态数据不以可执行业务 JS 加载。
- 测试、冻结 JS 对照、构建脚本属于开发工具，不计入生产界面边界，也不随游戏发布。

不改变玩法、客流规模、票价、模拟步长、历史长度或旧存档合同来换取迁移通过。确需格式或 API 演进时显式版本化。

## 3. 目标结构与接口

保留现有 Rust 模块，增量建立 CoreSession，不另复制一套已迁移算法。模块名称为规划建议，实施时可按依赖调整。

- CoreSession：World/Network、City、ForecastCatalog、JourneyRegistry、Runtime、Economy、History、Review、修订号及 RNG 的唯一可写所有者。
- Rust core：纯领域规则，可原生运行和确定性测试。
- Rust runtime：命令队列、时钟、任务修订、后台调度、快照与订阅。
- Rust web adapter：浏览器持久化、异步平台调用、Worker 启动及最小绑定。
- JS UI：不可写 ViewModel、表单草稿、展示与交互。

接口方向：
- open/new_session(region, source, options)
- dispatch(command_id, expected_revision, command)
- advance/pulse(monotonic_elapsed, budget, visibility)
- query/subscribe(view_kind, selection, since_revision)
- preview_import(bytes) -> import_token；confirm_import(token)
- export/save_checkpoint；close/dispose

命令返回批准的修订、事件和视图 patch；错误返回结构化错误码与必要参数，中文界面文案仍可在 JS。预览与提交复用同一 Rust 规则。

预览不消耗实际 RNG/ID、不扣款；提交有唯一命令号、修订校验与重复处理保护。超时后必须辨别命令是否提交，避免 JS 重发导致重复扣款。

CoreSession 先在现有 crate 内落地；确有依赖隔离需要再拆 crate。允许专用预测 Rust Worker 读取不可变快照，只有权威 session 能接纳结果；不把“全部 Rust”误做成全部任务串行阻塞同一线程。Worker 不可用时使用同一 Rust 核心的本地绑定路径。

- 预测任务接收不可变 Rust 快照，结果按 network/city/demand 修订接纳；迁移 UI 的 dirty/过期拒绝策略。

### P3-3：完整运行控制、时间与批次输出

依赖：P3-2。
工作：
- 默认模型的运行初始化、索引、列车模板、队列/车厢/统计/财务关联和时间债务统一进入 session。
- management/prepareTick/calendar 及 performance.createClock 的业务编排迁入 Rust；JS 只传脉冲、可见性和暂停/速度意图。
- Rust 内部使用结构化调用，移除每步为内部通信构造/读取数值 packet；复用临时缓冲。
- 批次只输出最终展示姿态、累计 patch 与确需显示的有序事件；保留对内部每步状态的测试观察接口。
- UI 插值读取姿态与时间戳，不以帧数决定生成乘客或结算金额。

完成条件：相同脉冲/命令序列的完整世界及运行快照一致；跨日、峰谷、开闭站、欠费/贷款切分、暂停/恢复及计算余量均对照。JS 不执行游戏小步回放。
收益重点：连续运营 CPU、每游戏分钟请求数、输入/输出字节和主线程任务。

- 异步队列、超时后提交辨识、任务失效、重试/回退与 Worker 生命周期策略在 Rust runtime/web adapter；手写 JS 桥接不保留状态机。
- 归并重复适配器和旧 ABI；测量各 WASM 实例的驻留，按需加载，统一缓存/回收所有权。预测隔离按实际负载保留。
- 若仍调用宿主 Math 作为原语，登记并迁入 Rust 数学实现或明确的系统绑定；随机与模型控制必须在 Rust。数学替换独立比对，避免浮点边界变化。
- 生产发布改用明确资源白名单；冻结 JS、旧 WASM 与测试夹具留在开发目录。资源版本升级配合缓存策略，避免旧 HTML 新核心混载。

完成条件：页面及全部 Worker 的生产依赖闭包只含 UI、已审计绑定和数据；无手写非界面 JS 实现。改 DOM/ViewModel 本地副本不会改变实际模型。平台事件不会触发第二套 JS 业务回退。
收益重点：维护面缩小、加载体积和多实例内存，浏览器操作完整性。

### P3-9：统一验收与迁移结项

## 5. 验证及性能口径

固定三种参照：
- 未 Rust：498c5cd2af607e60dd1c75a8ba5863c08ac5d4fa。
- 本轮起点：MAP65 / bffdd8f。
- 每阶段上一版：使用具体提交，不使用漂移的分支名。

对照同一输入、固定 RNG/时间/命令序列及累加顺序；完整状态哈希/逐字段一致，旧格式允许的缺省须先定义。新UI投影改变时，以 Rust 权威状态与稳定兼容导出对照，不要求保留旧JS对象身份。

每阶段报告：迁移函数与删除职责、剩余 JS 业务清单、规则结果、运行 CPU/耗时、冷事务、每游戏分钟请求/字节、GC后JS堆、ArrayBuffer、WASM内存、峰值RSS、浏览器交互和新增依赖体积。预期收益写机制，实测后才写百分比。

场景至少包括：
- 小/中线网、超过45,000实际定义及15万级预测目录，区分两类数量。
- 无线网/无需求、双地图、跨日/07:00、峰谷/开闭站、小数时间、30日历史。
- 运行中删线/改线/票价/交路、持续需求更新、撤销、退役几何、无路改签。
- 贷款切分/欠费停止与恢复、失败编辑/导入原子性、9MB以上保存与重载。
- 乱序/迟到后台结果、命令超时/重复、Worker不可用、内存回收与会话替换。

性能资料现状（来自仓库MAP65，非本计划新跑分）：
- 每30游戏分钟，10线 JS 45.970ms、Rust Worker 93.205ms；14线 JS 144.383ms、Rust Worker 156.478ms。
- 峰值RSS分别为JS 106.27/176.41MiB、Worker 200.48/340.73MiB。
- Worker事件循环延迟更低，但Node探针不等于浏览器FPS。
- 五个30分钟测量窗口累计，10线564次请求、约24.20MB输入输出；14线566次、约40.74MB。这些是传输优化线索，不是已完成的CPU归因。

迁移优先，内部数据调用与输出精简随对应阶段实施，不另设一轮先行性能大改。保持每阶段可运行、可回退，功能与性能分别验收。
