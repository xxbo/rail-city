# 核心 Rust 迁移盘点（P3-8源码 / P3-9待验收）

当前权威状态由 runtime_session / runtime_seed / forecast_session / platform / persistence 持有；原生JSON、存档、超时租约与只读投影已接入。运行与需求共用原生生命周期策略，界面退出备用模拟/诊断线程。最新职责见 [P3-8源码](rust-wasm-p3-8.md)，验收任务见 [P3-9准备](rust-wasm-p3-9.md)。当前产物目标core-v33/ABI6，P3-2以来统一构建及运行验收待执行，尚未形成迁移结项结论。

以下逐项记录保留此前验收历史；“JSON属于宿主”“JS回调兼容”等旧边界以本段和最新阶段记录为准，历史性能数字不代表当前源码实测。


P3-0已建立完整非界面迁移的生产AST清单、固定MAP65行为夹具与opt-in Rust会话合同，见[P3-0](rust-wasm-p3-0.md)。P0～P2的“规则范围完成”不代表状态/事务/平台层全部迁移；P3阶段逐函数去向和下一步见[完整计划](rust-ui-only-plan.md)。P3-1已接管初始化会话与数据生成，见[P3-1](rust-wasm-p3-1.md)；运行期完整所有权继续由P3-2～P3-8推进。

P0 与 P1-1、P1-2、P1-3、P1-4 已验收默认 routeModel 9 路径。按实际调用链记录职责；性能以同输入对照为准。P2-1 站线编辑链已整体完成并复核；P2-4完整文件/数据库入口验收、签名/城市/需求/恢复校验及旧加权时窗/发车规则已完成，见 [MAP65](rust-wasm-map65.md)。P2-3运营诊断/预测统计/告警/实际效果观察已完成，见 [MAP64验收](rust-wasm-map64.md)。P2-2建设/车库/设施资产事务也已完成，见 [MAP63验收](rust-wasm-map63.md)。站线编辑见 [MAP62 统一验收报告](rust-wasm-map62.md)；此前交路与容量单元见 [MAP61](rust-wasm-map61.md)、[MAP60](rust-wasm-map60.md)。P1 实现、验证和正负收益见 [P1 验收报告](rust-wasm-map59.md)；原始排期保存在 [迁移审计](rust-migration-audit.md)。

## P1 的具体完成条件

- **P1-1 / MAP57**：当前日和 30 日历史原生持有，自主跨日、历史查询与日报聚合；32 日完整对照通过。
- **P1-2 / MAP58–59**：线网变更、失效后缀、旧几何归档、候车/换乘/站外迁移和活跃定义重编号规则进入 Rust；默认 Worker 内完成运行中改签，继承原票价，找不到路径时沿用取消语义；高峰切换时更新原生图权重，保留原缓存语义。专项实际发生 22 次原生改签，主线程改签调用为 0。
- **P1-3 / MAP58**：设施候选选择、系统生成/升级、车站覆盖、分区评分、开发阶段、区域潜力、有限人口/岗位预算和分配、生长结算及城市汇总进入 Rust；陆地数据仍由地理适配器提供。
- **P1-4 / MAP58–59**：原生生成出行合同表，预测使用紧凑 DTO；每类预测视图最多保留 256 条，采样准备直接读数值元数据；线路连接、需求核算和站点预测从原生聚合查询获取。保持原预测、实际出行编号、票款及存档语义。

整理和城市更新仍是明确的低频事务边界；保存/结构编辑会临时读取完整运行快照。同步接口、旧模型及 Worker 启动失败的环境保留兼容适配，规则核仍可调用 Rust。地图、DOM、文件 API、IndexedDB 和标准 JSON/UTF-8 编码属于宿主职责。

## P2-1 整体验收（MAP60～62）

交路编译、几何/票价/两段容量校验及完整站线编辑命令已原生化。包括新建线路、增删/插入车站、近站合并、固定点与曲线、轨道复用/拆接、容量独立走廊、交路/跨线端点重映射、配置写入、世界/站线结构校验和配属约束读取、候选原子提交与撤销网络检查。默认值、当前网络升级/预设移除和站名迁移也复用原生规则。

宿主仅保留模板/地区/地名字典、标准编码、泛型应用/运行快照与批准结果应用，以及地图/DOM/图表显示。资产报价/扣款/购买库存已由P2-2接齐；预测统计及建议已由P2-3接齐；P2-4已接齐版本化验收、运行恢复与旧模型规则；保留标准文件/存储和身份投影。当前编辑调用链无需JS业务回退。

## P2-2 整体验收（MAP63）

建设报价、回收、资产差额、购车/库存/预留约束、扣款及台账、旧成本返还、手动设施命令与市政移交返还进入Rust。默认UI采用原生结构化事务；回调API保留兼容并由原生最终结算。764项资产对照/约束检查、83个回归套件及35项Rust单测通过，冷事务正负收益与完整运营双基线见 [MAP63](rust-wasm-map63.md)。

## P2-3 整体验收（MAP64）

预测分线/站点及全网统计、断面需求与运力、加减车和交路建议、预览/稳定分配、拥挤告警、实际效果采样/基线/窗口/中断/归因均进入Rust。诊断Worker一次调用合并建议和指标，复用紧凑数值目录，避免展开全部OD对象。观察保留原始时钟、实际样本与事件引用语义；浏览器只调度原生给出的到期时间。完整对照与双基线见 [MAP64](rust-wasm-map64.md)。

## P2-4 整体验收（MAP65）

文件格式、原有文本/结构/数值限制、地图/线网/城市/开发区/财务/满意度/观察检查、网络签名、运行恢复的目录/列车/退役几何/候车/站外/换乘/容量/占用/乘客守恒均由Rust规则处理。新增车上明细守恒、重复列车、有效腿段及未知恢复版本拒绝。导入失败保持世界和缓存计划原样。

`runtimeVersion:1`用于新文件与数据库负载；没有该字段的既有第7代存档继续接纳，第6代与裸旧状态保留原数据库迁移入口。数据库载入的版本/运行头和签名也由原生验收。旧加权路径继续使用原来的身份/流式队列适配，营业时窗和新列车字段已迁入Rust；避免强制建立第二份大目录身份索引。旧预测对象的定义构建按512条有界批次原生执行，恢复采用紧凑关联表，保留原乘客及票款合同。

默认紧凑目录恢复避免完整预测重建和重复构建；文件增强验收、签名和原始对象兼容路径仍有开销。完整测量与边界见 [MAP65](rust-wasm-map65.md)。P0～P2计划内规则迁移已收尾；后续性能优化应按真实热点、状态所有权和传输量单独验收。

## P3-1 初始化接管

`bootstrap.rs` 持有版本化数据、区域/枢纽派生、两地图世界与城市初始化、配置、命名随机调用顺序、旧启动状态修复和恢复选择。`SessionHost` 默认编入生产核心，负责初始化候选与会话替换。JS只转发初始化参数、通用值编码及显示。地理/配置返回只读兼容视图，活动世界仍通过现有适配器运行；预测目录、实时运行和编辑事务所有权按后续阶段收口。完整测量见[P3-1](rust-wasm-p3-1.md)。
